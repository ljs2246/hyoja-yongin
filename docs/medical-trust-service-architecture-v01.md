# 효자 의료정보 신뢰관리 시스템 v0.1 (설계 초안)
작성일: 2026-10-28
상태: 설계/시험용. 운영 앱 및 main 미반영. 전국 확대 보류.

## 목적
병원/약국 데이터 수집, 검증, 승인, 공개를 효자 고객 앱과 분리한다.
'자료 수집 성공', '인허가 운영 확인', '방문 시 영업 중'은 다른 개념이다.

## 분리 구조
1. source_adapters: 공공기관별 원본 수집. 원본 바이트/해시, 출처 URL, 자료 기준일, 수집 시각 저장.
2. staging: 원본을 보존하고 정규화 결과를 별도 저장. 실패/결측은 기존 공개본을 수정하지 않는다.
3. identity_matcher: hpid, HIRA 식별자, 지자체 인허가 관리번호를 각자 보존. 단순 이름 유사성으로 동일 기관 확정 금지.
4. verification_engine: 인허가 상태, 주소, 좌표, 연락처, 영업시간을 항목별 판정. 출처별 기준일 비교.
5. review_queue: 충돌/중복/폐업 의심/연락처 오류를 담당자가 검토. 원문 근거, 승인자, 승인 시각 기록.
6. publication: 승인된 스냅샷만 별도 읽기 API/파일로 발행. 이전 스냅샷 보관, 긴급 차단/롤백 지원.
7. audit_monitor: 일별 지역별 수집 수, 급감/급증, 누락, 검증 지연, 공개 보류 수 감시.

## 판정 원칙
- VERIFIED_LICENSE: 공식 최신 인허가 자료에서 운영상태 확인. 실시간 영업을 뜻하지 않음.
- VERIFIED_DETAILS: 기관명/주소/좌표/전화 등 해당 필드 공식 교차확인.
- REVIEW_REQUIRED: 공식 원천 충돌, 오래된 자료, 식별자 매칭 불확실.
- CLOSED_OR_SUSPENDED: 공식 인허가상 폐업/휴업 확인; 공개 검색 제한/명확한 표시.
- UNKNOWN: 확인할 수 없는 상태. 운영 중으로 추정 금지.
- OPEN_NOW: 별도 실시간 공식 영업정보와 시간대/임시휴무 확인 없이는 표시 금지.

## 안전 정책
- 원본 자료, 내부 검토 상태, 고객 공개 데이터를 서로 분리.
- 소스 오류, API 장애, 일별 건수 급감, 행정구역 불일치 시 자동 공개 차단.
- 휴폐업 신호는 자동 확정하지 않고 근거/자료 시점 확인 후 공개 정책 적용.
- 운영시간의 2500 등 비정상값을 임의 변환하지 않음.
- 전화번호 자리수 형식 통과만으로 실제 연결 확인 처리 금지.
- 신고는 참고 정보로 접수하되 공식 근거 없이는 고객 데이터 자동 수정 금지.
- 개인정보 및 결제정보 수집 불필요. 카드사/VAN 거래활동은 별도 법적·계약 검토 전 미도입.
- 운영 반영은 명시적 승인 후 별도 절차.

## 1차 검증 범위
용인 응급의료기관 5건, 약국 441건. 우선 검토: 가짜 전화번호 18건, 중복 의심 4그룹(9행), 2500 영업시간 2기관.
현재 숫자는 수집된 기록 수이며 운영 검증 완료 수가 아니다.

## 전국 확장 사전 준비
지역코드/기관종별/공식 소스별 어댑터 설계, 지역별 공개 게이트, 행정구역 교차오염 방지.
용인 기준 통과 전 전국 운영 배포 금지.

## 단계별 구현
A. 테이블/이력 구조를 테스트 브랜치에 설계한다.
B. 기존 용인 JSON에서 staging으로 읽기 전용 가져오기 및 검증 리포트 생성.
C. HIRA/인허가 원본 연결 가능성 확인, 실제 행 단위 대조.
D. 검수 대시보드와 승인 워크플로 시험.
E. 앱 공개 API는 용인에서 검증 후 승인받아 연결.

## 공개 전 필수 조건
실제 공식 원본 행 대조, 정확도/미확인 비율, 변경 감지 및 롤백 시험, 휴폐업 처리 시험, 담당자 승인 이력, Android/iPhone 사용성 검수.
