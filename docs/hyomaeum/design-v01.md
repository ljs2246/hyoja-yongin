## 2. 기존 기능과의 연동 설계 (충돌 없음)
- 기존 `family.js`(가족 전화·오늘의 안부)는 **한 줄도 바꾸지 않음**. 저장 키가 다름(`hyoja-family`·`hyoja-checkin` ≠ `hj-hyomaeum-v1`). 가족 이름·전화번호를 효마음이 읽거나 복사하지 않음.
- 전화 버튼은 그대로 두고, 통화 후 이용자가 직접 「안부 전화를 드렸어요」를 누르는 방식. 전화 링크 클릭을 감지해 자동 적립하지 않음(시험 모7).
- 향후 통합 시 선택지: (가) 오늘의 안부 카드 아래에 별도 카드로 배치(권장) (나) 안부 버튼과 합치기 → (나)는 「자동 확인」으로 오인될 수 있어 비권장. 통합 전에 아래 위협모델 평가 필수.

## 3. 포인트 규칙 (UI 시안용 가정값 · 규칙 버전 r1 · 최종은 이용자 검증 후 준식님 승인)
| 행동 | 적립 | 한도 |
|---|---|---|
| 안부 전화 자기기록 | 50 마음 | 하루 1회 |
| 안부 메시지 자기기록 | 20 마음 | 하루 1회 |
| 직접 방문 자기기록 | 100 마음 | 주 1회(월요일 시작) |
| 주간 보너스 | 100 마음 | 같은 주 전화·메시지를 기록한 날이 5일 이상일 때 주 1회. 연속 일수 요구·유지 압박 없음 |
- 날짜·주차는 한국시간(KST) 기준. 통화시간·광고 클릭·연락처 수집량과 연동 없음. 원화 환산 표시 없음. 감점·벌점·실패 표시 없음(「오늘은 건너뛸래요」 제공).
- 꽃 1송이 = 마음 100(표시용). 감사카드는 정해진 문구 3종에서 고르고, 문자 앱에서 이용자가 직접 보냄(번호 저장 없음).

## 4. 데이터 구조·개인정보 (최소 수집)
저장 위치: 이 휴대폰 localStorage 한 키. 항목: `anonymous_local_id`(무작위, 기기 안에서만), `local_date`, `action_type`, `reward_rule_version`, `credited_points`, `idempotency_key`, `created_at`, `deleted_at`(+ 주 구분값). **이름·전화번호·대화·통화내역·건강·위치 없음**(허용 목록 시험 통과).
- 중복키 = `기기 내 무작위 ID | KST 날짜(방문은 주) | 행동 | 규칙버전`. 저장 직전 재확인 + 브라우저 잠금(두 창 동시 시험 통과).
- 삭제: 항목 삭제(합계에서 제외, 같은 날 다시 받기는 불가 → 지우고 재적립 방지) / 전체 삭제(내부 ID 포함 모두 제거, 시험 통과). 저장 실패 시 조용히 바꾸지 않고 실패를 알림.
- 해당 없음/미구현: 계정·로그인·기기 간 동기화(기기 변경·분실·삭제 시 기록 소멸 안내 문구 필요), 미성년자·보호자 동의(법률 검토 후).

## 9. 구현 가능성 판단
- Phase 1(비금전 자기기록 데모): 기술적으로 가능, 이미 시안·시험 완료. 시범 오픈과 분리해 **격리 유지**.
- Phase 2/3: 서버 원장·법률·계약이 선행되어야 하며 지금은 구현 불가. 이용자 조사(오해율·불쾌감) 후 재판단.

## 10. 승인 필요·결정 사항
1. 기능 방향(비금전 자기기록 방식) 승인 여부 — 승인 전 확대 금지. 2. 포인트 규칙 r1 수치 승인(가정값). 3. 이용자 조사 계획(어르신·자녀 소수). 4. 법률 검토 착수 시점. 5. 데모 폴더를 main에 올릴지 여부(올리면 주소를 아는 사람은 접근 가능 → 비공개 유지 권장).
