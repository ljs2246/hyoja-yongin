# 효자 통합 안전·보안관리 체계 v0.1
작성일: 2026-10-29. 시험 브랜치 설계 문서. 운영 변경 없음.

## 보호 범위
- 앱/웹/서버, GitHub·CI/CD, API 키·계정, 의료정보 수집·공개, 가족·어르신 개인정보, 디자인·영상·채널 계정, 사업·계약·저작권.
- 목표: 예방, 탐지, 최소권한, 차단, 복구, 변경 이력, 사용자 승인.

## 운영 코드에서 확인한 위험
- main .github/workflows/update-data.yml의 '바뀐 자료 저장'은 if: always()로 실패해도 실행. 성공/실패 상태를 기록할 수는 있으나 부분 갱신 결과가 운영 데이터에 반영될 수 있음.
- main scripts/fetch_data.py는 의료기관 두 범주를 순차적으로 파일에 쓰고 마지막 status를 저장. 앞선 범주 성공 후 뒤 범주 실패 시 데이터가 부분 변경됨.
- main의 수집 코드는 각 구별 0건/주소 지역 혼입/기관 식별자 중복/전일 대비 급감 등의 검증이 부족함.
- main 갱신 작업에 contents:write 권한이 있음. 수집과 공개 권한을 분리하는 개선 필요.
- 이 사실들은 취약점/설계상 위험이며 침해사고 발생 증거는 아님.

## 제안하는 단계별 통제
1. 최소 권한: GitHub 관리자/배포자/검토자 권한 분리, MFA/패스키, 비밀키 저장소와 회전 절차.
2. CI 보안: dependency/secret scanning, branch protection, PR review, 테스트 통과 후만 merge, 배포 승인 환경.
3. 데이터 안전: 공식 출처·원본 해시·기준일·지역/기관 유효성 검증, staging 수집, 변경 요약, 승인된 스냅샷만 공개.
4. 개인정보: 최소수집, 전송/저장 암호화, 접근 로그, 보존기간·삭제 정책, 민감정보 처리 여부 점검.
5. 사고 대응: 등급(긴급/높음/보통), 위험 기능 비활성화, 비밀키 폐기/교체, 백업 복원 연습, 사고 기록 및 법적 신고기한 검토.
6. 사업 운영: 상표/저작권/개인정보/결제/광고문구/제휴/스토어 정책 점검표, 변경 승인 기록.
7. 주기 점검: 자동 검사는 CI와 모니터링 서비스에서 수행해야 실제로 상시 동작. 대화만으로 상시 감시를 보장하지 않음.

## 즉시 실행 우선순위
P0: 수집 실패 시 운영 데이터 자동 반영 차단, 임시번호/지역혼입/빈 자료 검증, 비밀키 노출 여부 점검.
P1: branch protection, 관리자 MFA, 백업·복구, 보안 업데이트, 실제 앱 권한/SDK 점검.
P2: 운영 대시보드, 변경 승인 워크플로, 정기 보안 검토와 침해 대응 훈련.

## 안전한 자동 대응과 승인 구분
- 자동 허용: 비정상 자료 격리, 수집 중단, 경보, 악성 요청 속도 제한(정책/오탐 검토).
- 승인 필요: 운영 코드 수정, 기관 공개상태 대량 변경, 계정 권한 변경, 키 교체로 서비스 영향 발생, 앱스토어 배포.
- 보안 사고의 긴급 차단 권한은 사전에 승인된 범위·롤백 절차가 있어야 함.
