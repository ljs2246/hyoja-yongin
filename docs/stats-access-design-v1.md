# 통합AI경영실 — 효자 통계 전용 읽기 권한 설계 (설계안, 아직 구현·연결하지 않음)

## 목표
통합AI경영실에서 **효자 통계만** 읽고, 다른 사업(아이랑, 라그릴스 등)의 데이터와 섞이거나 보이지 않게 한다.

## 구조 (4겹 분리)
| 겹 | 방식 | 막는 위험 |
|---|---|---|
| 1. 사이트 분리 | 효자 전용 GoatCounter 사이트 1개(예: hyoja 전용). 다른 사업은 각자 사이트 | 한 통계에 사업 데이터가 섞임 |
| 2. 계정 분리 | **효자 전용 계정**(또는 효자 사이트에만 권한이 있는 사용자)에서 키 발급. 아이랑 계정(`airang-daejeon`)과 키·메일을 공용하지 않음 | 키 하나로 다른 사업 사이트까지 조회 |
| 3. 키 최소 권한 | 통계 **읽기** 권한만 있는 키. 기록·내보내기·사이트 설정 변경 권한 없음 | 키 유출 시 데이터 변조·삭제 |
| 4. 중계 분리 | 경영실은 키를 직접 갖지 않고, **효자 전용 중계 작업**이 하루 1회 통계 합계만 가져와 `효자/통계/YYYY-MM.json`으로 저장. 경영실은 이 파일만 읽음 | 키가 경영실·브라우저·사이트 코드에 노출 |

## 조회 범위 (경영실에 보이는 것)
일·월 방문 수, 화면별 조회, 검색 횟수(종류·구별), 전화·지도·글자 크기 버튼 횟수, 화면 폭 구간 비율. 개별 방문 기록은 가져오지 않음(애초에 없음).

## 권한표
| 주체 | 효자 통계 읽기 | 키 보관 | 키 발급·폐기 | 다른 사업 통계 |
|---|---|---|---|---|
| 대표 | 가능 | — | 가능 | 각 사업 권한대로 |
| 통합AI경영실(효자 화면) | **가능(파일만)** | 없음 | 불가 | **불가** |
| 효자 중계 작업 | 가능(읽기 키) | 비밀 저장소(예: 저장소 시크릿 `HYOJA_STATS_KEY`) | 불가 | 불가 |
| 아이랑·라그릴스 화면/작업 | **불가** | 별도 키(공용 금지) | — | 자기 사업만 |
| 앱(사이트 코드) | 불가 | **키 없음**(방문 기록 전송은 키 없이 공개 이미지 요청) | 불가 | 불가 |

## 자동 안전장치 (구현 시 포함할 시험)
1. 중계 작업이 시작할 때 사이트 목록 조회(`/api/v0/sites`)로 **키가 보는 사이트가 정확히 1개(효자)** 인지 확인, 아니면 즉시 중단.
2. 가져온 모든 항목의 사이트 코드가 효자와 같은지 검사, 다르면 저장하지 않음.
3. 저장 파일 경로·이름에 `hyoja`가 없으면 거부(다른 사업 폴더 혼입 방지).
4. 키는 로그·보고서·화면에 출력하지 않음(마스킹 검사).
5. 호출은 초당 4회 이하(공식 한도)로 제한, 실패 시 재시도 횟수 제한.
6. 모의 서버로 "다른 사업 사이트가 섞인 응답"을 만들어 위 1~3이 막는지 시험.

## 운영 규칙
- 키는 90일마다 교체(예시 기준, 대표 결정), 퇴사·유출 의심 시 즉시 폐기.
- 키 발급 화면에서 권한이 "읽기"만 선택됐는지 대표가 캡처로 확인.
- 경영실에는 "효자 통계"라는 별도 메뉴로만 연결, 다른 사업 메뉴와 같은 데이터 저장소를 쓰지 않음.

## 공식 문서로 확인한 것 / 못 한 것 (2026-11-08)
- 확인: API 키는 **계정(사용자) 메뉴에서 발급**, `Authorization: Bearer` 인증, 권한이 없으면 403, 초당 4회 한도, 통계 조회·내보내기·사이트 목록/수정 등 엔드포인트 존재(goatcounter.com/help/api).
- **미확인**: 키 권한의 구체적 종류와 이름, 키가 특정 사이트로 한정되는지(계정 전체인지), 데이터 보관 기간. → 그래서 위 2겹(계정 분리)과 안전장치 1번(사이트 목록 확인)을 둠. 개설 후 `/api/v0/me`, `/api/v0/sites`로 실제 범위를 확인한 뒤 확정.
- 이 설계는 **대표 승인 전에는 계정 생성·키 발급·외부 연결을 하지 않음**.
