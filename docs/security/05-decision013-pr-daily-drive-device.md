- 재사용: 기존 `qa-test-branch.yml`에 `schedule: 0 23 * * *`(=08:00 KST) 추가. 새 워크플로우·새 보고서 없음. 06:30 자료 갱신 → 08:00 점검 순서.

- main 읽기 전용 점검: `HJ_ALLOW_MAIN_READONLY=1`은 예약 실행에서만 설정. 기본값은 계속 main 실행 거부(시험 통과).
- 실패 시: 해당 실행 중단(기존), 기록은 artifact 90일 보관(기존), **GitHub 이슈 1건 생성/댓글 추가**(`notify` 작업, `issues: write`만). 공개 저장소이므로 본문에는 실행 링크만 쓰고 번호·자료·로그는 쓰지 않음. 이슈 알림은 저장소 소유자에게 GitHub 메일/앱 알림으로 가며, 실제 수신 확인은 미검증.
- **중요한 한계:** GitHub의 예약 실행은 기본 브랜치(main)에 파일이 있어야 시작됩니다. 지금은 테스트 브랜치에만 있어 **8시 자동 실행은 아직 동작하지 않음**(미구현·승인 후 시작). main 변경 없이 할 수 있는 시험: ① 푸시마다 도는 자동 검수(통과) ② `scripts/daily-run.sh` 로컬 실행(통과 이력 있음) ③ 승인 후 수동 실행 1회.
- 이메일·메신저 추가 알림: 외부 서비스 연결 시 필요한 것 = 수신자 계정, 웹훅 주소(비밀 저장소 보관), 메시지에는 링크·상태만. 연결은 최소권한·정보 노출 검토 후 승인받아 진행(미구현).
- 대안(참고): 별도 예약 작업(Claude 예약 작업)은 새 계정권한·비용이 따를 수 있어 GitHub 방식을 우선 제안.
