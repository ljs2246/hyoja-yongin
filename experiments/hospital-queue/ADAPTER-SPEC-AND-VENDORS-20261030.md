# 병원 대기 어댑터 규격 + 공급사 비교표 (2026-10-30, 시험 브랜치 전용)

상태: **검수중 / 공급사 API 미확인 / 실제 연동·발송 0건.** 아래 "제안 계약"은 우리가 병원·공급사에 요구할 형식이며, 공급사가 제공한다고 확인된 것이 아니다.

## 1. 공통 구조 (A·B 두 방식이 같은 엔진을 쓴다)
```
[A 공급사 웹훅] ─서명검증→ ┐
                           ├→ ingest(store, canonicalEvent, {authenticated}) → 엔진(queue-core.js) → snapshot() 화면 / outbox → 문자 게이트웨이
[B 효자 직원 보드] ─로그인→ ┘
```
- 인증은 **어댑터만** 판정한다(`authenticated`). 이벤트 본문의 `verified:true` 같은 자기주장은 무시.
- 엔진은 네트워크·문자·전화번호를 모른다. 수신자는 `recipientRef`(불투명 참조)이고, 실제 번호는 별도 보관소에서 발송 직전에만 조회.

## 2. 표준 이벤트 (canonical event)
| 필드 | 형식 | 규칙 |
|---|---|---|
| eventId | 문자열 ≤64 | 유일. 재전송 시 동일 값 → 중복 처리 |
| sequence | 정수 ≥1 | **대기열 단위** 단조 증가. 이하/중복 거부, 51 이상 점프는 대기열 차단 |
| hospitalId, queueId, ticketToken | 문자열 | 3개 모두 일치해야 접수 적용. 미등록이면 자동 생성하지 않고 거부 |
| type | waiting, queue_changed, paused, resumed, delayed, called, completed, cancelled | 그 외 거부 |
| peopleAhead | 정수 0~500 | waiting·queue_changed 필수 |
| observedAt | 밀리초 | **병원이 관측한 시각.** 현재+30초 초과 거부, 접수의 이전 관측보다 과거면 거부. 화면 신선도(2분)는 이 값 기준 |
| estimate | {min,max} 분, 0≤min≤max≤240 | 인증된 출처가 같은 이벤트에 실어 보낸 경우만 표시. 인원이 바뀌면 사라짐 |

## 3. 어댑터 인터페이스
| 어댑터 | 함수 | 책임 |
|---|---|---|
| A 웹훅 | `verifyWebhook` / `receiveWebhook` / mapper | HMAC-SHA256(secret, timestamp+"."+rawBody), 허용 오차 5분, 상수시간 비교. 공급사 필드가 확정되면 mapper만 교체 |
| B 직원 보드 | `staffBoard(...).emit` | 직원 로그인 필수(현재 목), 순번 자동 증가, 오타 접수번호는 거부 |
| 문자 | `deliverable` → 게이트웨이 → `markResult` | 발송 직전 상태 재확인, 실패 재시도(최대 3회, 백오프), 결과 불명은 자동 재발송 금지 |
| SENS | `buildSensSmsPayload` | 본문만 생성(DRY_RUN_ONLY). 필드명은 공식 문서 대조 전 |

## 4. 제휴 없이 가능한 범위 (엄격 제한)
허용: 병원 공식 예약·접수 링크 열기, 기기 안의 개인 일정 알림("접수 후 N분 지나면 확인하세요" 같은 **본인이 설정한** 알림).
금지: "실시간 순번/대기 인원" 표시, 병원 시스템 화면 긁어오기, 추정 대기시간.
화면 문구 예: "병원 공식 접수 화면으로 이동해요. 이 앱은 병원의 실시간 순번을 알지 못해요."

## 6. 결론
- **지금 병목은 코드가 아니라 병원의 순번 데이터 접근 권한**이다. 공개 자료에서 어느 공급사도 외부 앱용 API/웹훅을 확인하지 못했다(= 없다는 뜻이 아니라 **미확인**).
- 그래서 **B(직원 보드)를 먼저 파일럿 가능한 형태**로 만들고, A는 공급사 답변이 오면 mapper만 바꿔 붙인다.
- 문자 발송은 SENS를 쓰더라도 발신번호·템플릿·단가·동의 절차가 끝나기 전에는 발송하지 않는다.
