# 효자 병원 진료 대기 순번 시범 설계 — 시험 전용 (2026-10-30)

**운영 상태: 기능 연구 및 로컬 시뮬레이터. 실제 병원 API·키오스크·문자 서비스 연결 없음. 고객 정보 수집 없음.**

## 이 파일이 있는 이유
병원에서 접수한 어르신에게 '내 앞에 몇 명 남았는지', '예상 대기시간(신뢰할 수 있는 경우만)', '호출 임박'을 쉬운 화면과 문자로 알려주는 기능의 실현 가능성을 가상 데이터로 검증한다. 똑닥 등 기존 서비스에도 유사 기능이 있으므로 경쟁 우위는 아직 검증되지 않았다.

## 구성
- `queue-engine.js`: 모의 접수 이벤트 상태 전이·중복 방지·갱신 지연 차단·발송하지 않는 문자 미리보기
- `queue-engine.test.cjs`: Node.js 내장 테스트 18개 (명령: `node --test experiments/hospital-queue/queue-engine.test.cjs`)
- 실제 SMS/알림톡 전송 코드, 개인식별정보, 통신 API 키, 환자 데이터 파일은 없다.

## 허가된 병원 연동 때 필요한 필수 데이터 — 아직 수신하지 않음
```json
{
  "eventId": "병원 또는 통합시스템에서 유일한 이벤트 ID",
  "sequence": 31,
  "ticketToken": "환자와 연결된 단기 난수 토큰",
  "hospitalId": "협력 병원 식별자",
  "queueId": "진료 대기열 식별자",
  "type": "waiting|queue_changed|called|cancelled|paused",
  "peopleAhead": 3,
  "observedAt": "병원 서버에서 실제 업데이트한 시각",
  "estimatedWait": null
}
```
위 데이터 계약은 **제안서**이며 실제 병원에서 제공한다고 확인된 형식이 아니다. 병원 현장 호출이 우선이고 대기시간은 진료실별 진료 상황에 따라 달라질 수 있다. 실제 ETA 제공에는 신뢰 가능한 공식 이벤트·오차 측정·표시 기준이 필요하다.

## 안전 관문
1. 병원·원무팀·EMR/HIS·키오스크 운영사 **모두에게 필요한 계약/허가 경로 확인**. 공개 응급실/약국 API는 개인 접수·순번 정보를 제공하지 않음.
2. 개인정보 처리 주체·위수탁/제3자 제공·환자 동의·자녀 수신 시 환자 의사 확인·최소 보관·암호화·접근 기록 검토. 진단명·진료과·민감정보는 SMS에 넣지 않음.
3. 발신번호 등록, 카카오 비즈채널·템플릿 승인, 발송 요금 및 실패·중복·오발송 처리 정책 확인.
4. 장애·정보 지연·취소·진료 호출 시 상태를 정확히 표시. 갱신 2분 초과시 '현재 대기' 수치 숨김(실제 운영 임계값은 병원별 합의 필요).
5. 실제 병원 연결이 불가능하면 '공식 예약 연결' 수준으로 제한하고 실시간 대기라고 주장하지 않음.
6. **시험 브랜치에만 보관**. main 병합, 운영 배포, 병원 외부 연락·계약, 환자번호 수집, 문자 발송, 유료 가입은 준식님 승인 전 금지.

## 용인 협력 병원에 질문할 항목 (승인 후 연락)
- 병원 내부 접수/대기 시스템, 키오스크/EMR 공급사, 외부 연동 API·웹훅 지원 여부와 계약 주체
- 접수번호와 실제 진료 순번의 차이, 대기 순서 업데이트 간격, 소아/응급/예약 환자 우선규칙
- 병원이 이미 제공하는 SMS/알림톡과 중복 통지 문제
- 데이터 제공·수신·유지 책임, 장애 대응, 고객 동의, 보존 기간, 비용 및 과금 주체
- 파일럿 대상 병원 1~2곳, 시범 기기 및 최소 데이터로 가능한지
